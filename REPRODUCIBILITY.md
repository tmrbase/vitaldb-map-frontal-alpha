# Source-to-result reproducibility

## Scope

The repository contains code, pinned environments, and a compact catalogue of
public file/header metadata from PhysioNet VitalDB v1.0.0. It contains no
waveform, clinical value, or derived row-level data. All downloaded inputs and
generated results are written below `data/` and `outputs/`, which are ignored by
Git.

## Data flow

`scripts/run_source_to_result.py` is the only complete-workflow entry point. In order, it:

1. downloads the official PhysioNet VitalDB v1.0.0 metadata, reconstructs the
   candidate set from the version-matched track catalogue, downloads the
   required `.vital` records in parallel from the public AWS S3 mirror listed
   by PhysioNet, and verifies their official SHA-256 digests;
2. reconstructs the no-recorded-positive-end-tidal-volatile prescreen;
3. creates quality-controlled maintenance windows and sustained low-MAP event subwindows;
4. extracts the two pre-event intervals, additional physiological covariates, and ECG-derived HRV measures;
5. calls `scripts/run_analysis.py` for the original Python patient-influence ranking,
   reported R analyses (including the patient-exclusion refit and spectral joint tests),
   and aggregate reporting assets; and
6. compares regenerated cohort counts and numerical results with `expected_results.json`.

The reporting stage writes Figure 1 and Supplementary Figures S1–S4 to `outputs/release_assets/`. Figure S1 is generated from the regenerated cohort-flow counts rather than copied from the submission package.

The source stage downloads 1,577 candidate files (approximately 35.7 GiB), not
the complete 95.4 GB archive. Transfers are parallel, resumable, written through
`.partial` files, and atomically promoted only after SHA-256 and size checks.
Verified existing downloads and case-level extraction shards are reused unless
`--force` is supplied for derived products. Verified source downloads are still
retained with `--force`; use `--force-download` only to repeat the network
transfer. `--skip-fetch` is valid only when `data/vitaldb` already contains the
verified v1.0.0 files produced by the repository fetch script.

## Environments

Python 3.12 dependencies are pinned in `uv.lock`. R dependencies are pinned in `r_analysis/maintenance_ra/renv.lock`, and the development session is recorded in `R_session_info.txt`.

```powershell
uv sync --frozen --extra dev
Rscript -e "if (!requireNamespace('renv', quietly=TRUE)) install.packages('renv'); renv::restore(project='r_analysis/maintenance_ra', prompt=FALSE)"
```

For a nonstandard R installation, pass `--rscript <path>` to the workflow driver.

## Statistical implementation boundaries

The primary repeated-measures models use `nlme::lme`, `nlme::corCAR1`, and `splines::ns`. Patient-cluster covariance for the primary MAP contrasts uses `clubSandwich::vcovCR(type = "CR1S")`; event-centered linear-model covariance uses `sandwich::vcovCL`. Closed-form weighted least-squares helpers are used inside the 2,000-replicate patient bootstraps for event-level summaries. The influence diagnostic uses its specified Python spline basis and random-intercept CAR(1) fit, then holds covariance parameters fixed while deleting each patient's GLS contribution. These diagnostic calculations do not replace the primary mixed-model implementation or the R refit after exclusion.

The Table SVI estimates and bootstrap confidence intervals concern the 0–1-minute
interval. Its reported Global P values jointly test all four post-event coefficients
with a surgery-cluster-robust Wald test. The absolute-alpha Global P values are
generated by `06_event_spectral.R` from the **same rows, design matrix, alpha
response and event/pair weights** used by `20_alpha_nonalpha_decomposition.R`.
Both scripts call `R/event_components.R`. Script 06 uses surgery-cluster HC1
covariance with cluster adjustment and a four-degree-of-freedom chi-square Wald
test. It aborts on any point-estimate or cohort disagreement with script 20's
saved results. The patient-bootstrap CIs remain script 20's unchanged outputs.

## Validation

Fast validation does not require source records:

```powershell
uv run python -m pytest -q
uv run python -m ruff check scripts revision_sensitivities src tests
uv run python scripts/run_source_to_result.py --dry-run
uv run python scripts/validate_release.py
```

Unit tests protect the pinned environment/catalog, EEG filter guard, Welch segment count,
event t=0 definition, 50%/80% interval-completeness rules, subwindow-level non-alpha
calculation, and patient deletion against direct GLS on a synthetic cohort. The R
test checks rounding up 1% of patients, excluding all their surgeries, and rejecting
stale/duplicate/nonfinite rankings. The release validator also checks workflow order
and use of standard spline and patient-cluster covariance implementations.

After a complete run, `scripts/validate_release.py --generated-results` verifies the 904-patient, 914-surgery, 21 192-window cohort and the manuscript-critical numerical targets. Tolerances are used instead of byte-for-byte comparison because serialisation and graphics metadata can vary across platforms.

`scripts/validate_release.py --diagnostics` checks only the focused
outputs and random-slope diagnostics: reliability and split-half values
at published precision, the generated patient ranking used by the R refit,
894 patients / 904 surgeries / 20,725 windows after exclusion, and the four-interval
spectral Global P values. Passing this focused check is not a complete source-to-result run.

For a focused check using existing local script-20 outputs, run script 06 from
`r_analysis/maintenance_ra`, then `python scripts/validate_release.py --spectral-consistency`
from the repository root. This checks all four alpha coefficients against both
the script-20 JSON and CSV, cohort sizes, and the fixed P targets.
No waveform extraction, maintenance-model refit or bootstrap rerun is implied.

From `r_analysis/maintenance_ra`, run
`Rscript --vanilla ../../tests/test_component_joint_test.R` to compare WLS and
surgery-cluster HC1 against independent normal-equation and sandwich calculations
on synthetic data with unequal interval availability and multiple events per surgery.

## Runtime and upstream changes

Downloading the public records, processing waveforms, and completing the
2000-replicate patient bootstrap can require many hours. Use `--workers` to set
both concurrent downloads and parallel processing. A dry run lists all commands
without changing data or results:

```powershell
uv run python scripts/run_source_to_result.py --dry-run
```

The source is fixed to the DOI-versioned PhysioNet v1.0.0 archive. If a validator
fails, audit file digests, package versions, and cohort attrition;
`expected_results.json` must not be replaced without scientific review.
